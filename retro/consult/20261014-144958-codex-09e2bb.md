## ① 逐条 P 级裁决

| R4 finding | 裁决 | 理由 |
|---|---|---|
| 1. 运行任务越过磁盘水位 | **暂定 P2，不接受“最多越界 680 MB”的理由** | 8 是等待中加运行中的任务数；85 MB 只是一次实测文件大小，代码没有单文件上限。现有证据不足以证明真实部署会因此崩溃，故不能直接定 P1；若确认与其他服务共盘且正常负载可耗尽空间，应升 P1。 |
| 2. 失败注册表保留 traceback | **P2，同意修复** | 1024 限制的是条目数，每条仍持有异常和 traceback，可能连带保留帧内缓冲。修复时保留 **400/404/502 类别及已脱敏、限长的错误文本**，不能只存原始 `str(exc)`。 |
| 3. 非法 Range 返回 200 | **P3，驳回为阻塞项** | 对非法范围选择忽略并返回完整内容，符合 [RFC 9110 §14.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)；现有测试也锁定了该行为。 |
| 4. 新鲜孤儿 `.part` 留到 TTL | **P2，建议本轮修** | 启动扫描有 600 秒宽限，但周期清理只按 72 小时 TTL 删除 `.part`，水位淘汰只处理 final。水位紧张时应回收**已过宽限且不属于运行任务**的 `.part`，不能误删正在写入的文件。 |
| 5. 部署缓存路径不可写 | **P2，必须修** | 默认目录是 `/data/space-cache`，镜像以 uid 10001 运行；两份 compose 均未启用通向该目录的可写挂载。默认部署路径下此功能会以 502 失败；实际生产是否另有覆盖尚未知。 |

## ③ 主脑漏掉的

- **同一 finding 重审要按同一根因记账。** R4-1 是 R3-3 的剩余风险，不能因换了表述算一个全新问题；但它仍消耗一次 gate 轮次。先前的 680 MB 论证不成立，因此也不能直接以“无新事实”驳回。
- **水位检查与磁盘满不是同一承诺。** 当前代码能在 ENOSPC 后清理自身产物，却不能保证同盘其他服务仍有预留空间。是否共盘、生产 `SPACE_CACHE_DIR` 的实际值、其他服务的写入负载均未核实。
- 我无法读取 PR #45 的评论全文或当前 gate 结论；本次依据是本地提交和 payload。按任务说明，我是 R3 修复轮执行者，**对 R3-3 残余有自身实现利益冲突**；R4-1 的最终接受应由未参与实现者按部署事实复核。
